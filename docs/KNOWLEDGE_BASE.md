# Agent Apply: Knowledge Base & Applicant Memory Architecture

Agent Apply uses an evidence-grounded Retrieval-Augmented Generation (RAG) architecture to tailor job applications without hallucinating skills, metrics, or experiences. The applicant's career history serves as the durable **Knowledge Base** that grounds every resume bullet point, cover letter paragraph, and ATS screening answer.

---

## 1. Knowledge Base Directory Structure

All applicant knowledge base data is located in `data/profile/`:

```text
data/profile/
├── profile.yaml             # Active primary applicant knowledge base
├── schema.yaml              # Schema specification for valid profile YAML
├── profile.example.yaml     # Clean template for creating new profiles
├── active_profile.txt       # Pointer to current active profile (e.g. "default")
└── profiles/
    └── default.yaml         # Stored profile preset
```

## 2. Core Knowledge Base Components

### 2.1 Identity & Authorization (`identity`)
Defines legal name, contact information, portfolio links, citizenship, and work authorization status. The agent checks these constraints first to eliminate unviable job matches (e.g., jobs requiring active clearance or lacking sponsorship).

### 2.2 Education (`education`)
Captures institutions, degrees, GPA, honors, and coursework tagged by domain (`algorithms`, `distributed-systems`, `ml`). Course tags allow the agent to highlight relevant academic rigor for entry-level or research-oriented roles.

### 2.3 Work Experiences & Impact Pool (`work_experiences`)
Contains past professional roles with structured bullet points:
- `text`: Action-oriented bullet point following the Google XYZ formula: *"Accomplished [X], as measured by [Y], by doing [Z]"*.
- `tags`: Domain identifiers (e.g., `["fastapi", "kafka", "distributed-systems"]`).
- `impact`: Quantified outcome metric for semantic fit ranking.

### 2.4 Projects Portfolio (`projects`)
Showcases open-source contributions, research projects, and systems architectures with technology stack lists and live repository URLs.

### 2.5 Skills Taxonomy (`skills`)
Categorized technical proficiency:
- `languages`: Programming and scripting languages.
- `frameworks`: Application and web frameworks.
- `databases`: SQL, NoSQL, and vector storage engines.
- `tools`: DevOps, cloud infrastructure, and CI/CD utilities.
- `domains`: High-level specialization (e.g., SDE, Cloud Architecture, Generative AI).

### 2.6 STAR Story Bank (`story_bank`)
Pre-crafted behavioural interview answers organized by theme (`technical_challenge`, `leadership`, `ownership_impact`, `conflict_resolution`) structured into:
- **Context**: The problem environment.
- **Action**: What specific decisions and engineering actions were taken.
- **Result**: Quantified business or technical outcome.

### 2.7 QA Bank (`qa_bank`)
Deterministic screening answers for standard ATS application questions (e.g., visa sponsorship, years of experience, target compensation, availability notice period).

---

## 3. How the Agent Uses the Knowledge Base

1. **Job Scraping & Keyword Extraction**: The agent ingests job descriptions via ATS APIs or LinkedIn scraping, extracting core competencies and requirements.
2. **Semantic Matching & Scoring**: pgvector compares job requirements against applicant knowledge base skills and experiences.
3. **Evidence-Grounded Generation**: Resumes and cover letters are generated by selecting and adapting bullets strictly from the knowledge base — **no fabricated metrics or unverified tools**.
4. **Human-in-the-Loop (HITL) Gate**: Prepared documents are placed into the Review Queue for applicant approval before any submission action is taken.

## 4. Customizing Your Knowledge Base

To load your own profile:
1. Copy `data/profile/profile.example.yaml` to `data/profile/profile.yaml`.
2. Edit your career details, projects, and impact metrics.
3. Or use the Web Console UI at `http://localhost:8000/profile` to edit your profile interactively.
